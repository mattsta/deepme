# Platform Invariants — the release's contract with itself

Every self-management guarantee the platform claims, with where it is
enforced and where it is tested. A change that breaks a row breaks the
release. (Produced by the pre-release architecture audit; refresh it when a
row's enforcement or test moves.)

| #   | Invariant                                                                                                                     | Enforced                                                                                                                  | Tested                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| I1  | No external traffic is required for admitted work to progress: the maintenance timer reconciles → revives → pumps → prunes    | `balancer/server.py` `_lifespan`/`_reap_stale_jobs`/`_revive_backends`                                                    | `test_balancer_integration.py: finished_slots_free_without_any_client_poll`, `dead_replicas_jobs_are_presumed_lost`, `unhealthy_backend_is_revived` |
| I2  | Occupancy and work are separate operations; a submission round-trip never counts as a timed job                               | `balance.py` `reserve/release/record_inline` vs `begin_job/end_job`                                                       | `submission_is_not_recorded_as_a_finished_job`, `occupancy_moves_to_the_job_not_the_call`                                                           |
| I3  | One identity per job across ticket handover — verdicts, download, persistence all key on the harvested id                     | `media.py _poll` one-identity rule; balancer ticket rewrite                                                               | `test_media_client.py: download_uses_the_harvested_job_id`, `dead_ticket_with_a_known_job_is_followed_not_resubmitted`                              |
| I4  | Ticket ids unique across balancers and boots (name + boot-nonce salt)                                                         | `admission.py` salt; `balancer/server.py`                                                                                 | `test_admission_queue.py: ticket_ids_carry_the_queue_salt`                                                                                          |
| I5  | A ticket reaches at most one replica; cancel cannot race a wire-borne submission                                              | `admission.py claim/release_claim`, SUBMITTING refuses cancel                                                             | `claimed_ticket_is_invisible_to_the_next_pump`, `cancel_is_refused_while_the_submission_is_on_the_wire`                                             |
| I6  | Tests can never reach live infrastructure                                                                                     | `tests/conftest.py` autouse: remote.\* raises, host poisoned                                                              | self-enforcing by construction                                                                                                                      |
| I7  | First ^C cooperative, second immediate; every generation inherits the cancel signal                                           | `interrupts.py`; `media.py` default cancel                                                                                | `test_batch.py: interrupt_protocol_is_two_stage`, `every_generation_inherits_the_cancel_signal`                                                     |
| I8  | Balancer membership (incl. draining, first-fetch times) survives crash-restart; explicit start = fresh freeze                 | `balancer/server.py` atomic persist/restore; `balancerctl.start` rm                                                       | `membership_survives_a_crash_restart`, `draining_survives_a_crash_restart`, `first_content_fetch...`                                                |
| I9  | A resize converges from any intermediate state                                                                                | `switch.py execute_switch` reconcile pass                                                                                 | `test_switch.py` (9 scenarios: failed attach, leftover drain, stale backend, orphan balancer, drain-abort, force, queue-guard, repoint)             |
| I10 | Every fleet mutation is in the runs ledger                                                                                    | per-command `runs.record` (switch begin/outcome, balancer/gateway start/stop, serve ops, patches, store, reclaim, reboot) | switch outcomes via `test_switch` audit assertions                                                                                                  |

| I12 | Occupancy is rebuilt from replica truth at boot                                                                               | `balancer/server.py _recover_occupancy` before routing                                                                    | `boot_recovers_occupancy_from_replica_truth`                                                                                                        |

| I14 | Detach refused while a backend owns jobs or has a submission on the wire                                                      | `balance.detach`                                                                                                          | `detach_refuses_while_work_is_running`, `detach_is_refused_while_a_submission_is_on_the_wire`                                                       |

Known open gaps, deliberately flagged in code: durable admission journal
(`admission.py` header), multi-modality admission (`_admit`), `reprioritise`
unexposed, adaptive batch pool, cross-fleet scheduling, I11/I18/I22-CLI test
seams.
